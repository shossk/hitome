# ADR-0001: 撮影ランタイムに Godot を採用する

- Status: Accepted
- Date: (記入)

## 背景

組み合わせアセットの見た目チェックのため、3D シーンを組み立てて
ヘッドレス環境 (CI) で大量にスクリーンショットを撮る仕組みが必要。

## 決定

Godot 4 (gl_compatibility レンダラ) を撮影ランタイムとして使う。

## 理由

- OSS かつ単一バイナリで、CI コンテナへの導入がコマンド 2 行で済む
- ライセンス管理 (シート数・アクティベーション) が不要
- CLI 実行が第一級市民 (`godot --path ... -- args`)
- gl_compatibility レンダラは Mesa llvmpipe (ソフトウェアレンダリング) で安定動作し、
  GPU の無い CI ランナーで完結する

## 却下した代替案

- **Unity**: バッチモードは強力だが、CI でのライセンス認証と
  コンテナイメージの重さが個人規模の運用に見合わない
- **Blender (bpy)**: 静止画レンダリング品質は高いが、
  「製品と同じランタイムの見た目で確認したい」という要件
  (実機に近い描画での確認) から外れる
- **three.js + Puppeteer**: TS で完結する魅力はあるが、
  ゲームエンジン上のアセット挙動 (インポート設定・マテリアル) を検証できない

## 影響

- GDScript を少量書く必要がある (撮影ループのみ。ロジックの重心は TS 側に置く)
- CI では --headless が使えない (レンダリング無効化されるため) ので
  xvfb を併用する。ADR-0002 参照
